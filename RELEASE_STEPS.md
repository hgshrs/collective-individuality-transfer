# Release steps (for the author; not part of the reproduction instructions)

The tree in this directory was generated by `scripts/91_build_public_repo.py` from the private working repository
(history rewritten to drop the excluded files; one extra commit adds README, LICENSE, LICENSE-docs, CITATION.cff,
.gitignore and this file). Do not edit files here by hand: change the private repository (or `public_repo/` in it)
and rebuild. Placeholders to fill after publishing: `10.5281/zenodo.XXXXXXX` (README.md, CITATION.cff),
`https://osf.io/XXXXX` (README.md), `date-released` (CITATION.cff; the date of release v1.0.0).

1. **Create the GitHub repository** (public, empty: no README, no licence, no .gitignore). The name used here is
   `collective-individuality-transfer`; if you choose another name, replace it in README.md and CITATION.cff
   (in `public_repo/` of the private repository) and rebuild, or edit after the first push and commit.

2. **Push the generated history** (branch `main`; the history was rewritten, so a fresh remote is needed; no
   `--force` is required on an empty repository):

   ```bash
   cd ~/public/collective-individuality-transfer
   git remote add origin https://github.com/hgshrs/collective-individuality-transfer.git
   git push -u origin main
   git push origin --tags        # phase0_done ... phase3_done (lightweight tags, rewritten hashes)
   ```

3. **Zenodo DOI**: log in to Zenodo with GitHub, enable the repository under *GitHub* in your Zenodo account, then
   create a GitHub Release `v1.0.0` (tag `v1.0.0`, title = paper title). Zenodo archives the release and issues a
   DOI (plus a concept DOI for all versions). Upload the supplementary archive (submission TIFFs, raw simulation
   outputs `sim_runs*.parquet`, participant-level result files; see the manifest written by the build script next to
   the output directory) as a separate Zenodo record or as extra files of the same record.

4. **Write the DOI back**: `CITATION.cff` (`doi:` line), `README.md` (header), the Methods / Code availability
   statement of both manuscript versions, and the OSF registration Description. The OSF registration cannot be
   edited once submitted, so obtain the Zenodo DOI (and the public first-commit hash printed by the build script)
   **before** registering on OSF. Commit the DOI edits in the private repository (`public_repo/`), rebuild, and push
   again (a rebuild rewrites the same history and adds the same final commit with the new content; if the remote
   already has the first push, use `git push --force-with-lease origin main` or push the edits as a new commit on
   top instead of rebuilding).

   > https://github.com/hgshrs/collective-individuality-transfer (archived at Zenodo, DOI
